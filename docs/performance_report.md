## 3. 根因分析记录（三次典型，完整版见 architecture.md）

| # | 现象 | 根因 | 修复 | 指标前后 |

## 4. Day 5 执行结果（2026-09-05）

### 4.1 L2 LLM 评估（20 题，prompts_l2.txt，判定口径：结论含关键数字且来自工具返回）

| 组 | 题目 | 判定 | 说明 |

## 5. 硬件与部署限制说明（如实）

1. **单机本机环境**：压测为 Windows 单机 + 本机 MySQL；**多实例水平扩展（线性度 ≥80%）与集群级 HA 无法在本地实测**——需 2+ 台 Linux 部署 systemd/K8s + 负载均衡后补测（deploy/ 工件已备）。
2. **LLM 层未计入压测口径**：P95 230ms 是纯工具最坏情况；真实端到端含 LLM 推理（秒级），须接入 Reasonix/Langfuse 观测后给出完整链路数字。
3. **可用性 99.9%**：组件级自愈已演练（无状态 + 重启即恢复）；99.9% 需监控告警 + 多实例支撑，属生产部署验收项，非本机可证。
4. **Token/缓存命中率**：依赖 DeepSeek 侧计费日志与 reasonix 会话统计，本机未量化；官方口径长会话 90%+。
5. **突破成本**：线性度/可用性硬验收需 ≥2 台云主机（按需，约 2×¥xxx/月）+ 对象存储/可观测平台；如引入 DynamoDBSaver 需 AWS 账号。

## 6. 容量规划（基于实测外推）

- 单实例（池 20）：~115 QPS 纯工具；真实 Agent 场景 LLM 主导，工具调用间秒级间隔 → 单实例可支撑 ~30-50 并发会话
- 目标「成百上千人」：按高峰 500 并发会话估 → 需 10-15 实例（保守），前置 LB + 连接池按实例数配（池/实例 ≈ 并发/实例）
- MySQL 侧：本机单实例已扛 115 QPS 无压力；生产按 sales 量级评估索引与慢查询（explain_query 工具已备）
